## 0. 速览

- 你的做法本身是对的：查询被化成“对区间 $[t+1,r]$ 依次作用函数
  $f_i(x)=x+a_i\ (x\ge b_i)$，否则 $x$”，用线段树维护分段复合函数，查询 $O(\log^2 n)$。
- 你代码里**只有一个逻辑错误**：进入函数复合前的初值 `K`。
  - 原来：`K = min(b[lt], k) + U - k`；
  - 正确：`K = (b[lt] <= k) ? b[lt] + U - k : k`。
  - 反例：$n=1,a_1=5,b_1=100$，查询 $(1,1,2)$。正确答案是 $2$，你的公式给出 $5$。
  - 性质 A（$a_i=1$）下 $U=k$，两个公式恰好相等，所以性质 A 全过。
- 其余问题都不是“做法错”，而是实现问题：
  - RE：内存约 372 MB（$2\times 10^6$ 个 `vector` 头 + $O(n\log n)$ 个 `pair<LL,LL>`）。
  - TLE：递归 + 每结点二分 + `vector` 访存，$n=q=5\times10^5$ 要 5～9 秒。
  - 编译：`#define NDEBUG 1` 之后 `assert` 在部分编译器上未声明。
- 常数优化后（同一做法）实测 1.96～2.64 秒、峰值内存 169 MB，17 组大样例全过。
- 单 log 做法：把答案化成“静态序列上第 $x$ 个 0 的位置”，用两棵主席树同时二分，$O((n+q)\log n)$。

## 1. 基础模型

### 1.1 取 0 模型

设查询展开后的序列为 $d_1,\dots,d_M$，其中 $d$ 是 $a_l$ 个 $b_l$、$a_{l+1}$ 个 $b_{l+1}$……依次拼接。
令 $c_i=\min(d_i,i)$，$S_i=\{p_1,\dots,p_i\}$。

**事实 1.** 对 $i=M,M-1,\dots,1$ 依次执行“取出当前集合中第 $c_i$ 小的数，然后删除”，第 $i$ 次取出的数就是 $p_i$。

**证明.** 对 $i$ 归纳。处理到 $i$ 时，已经删掉了 $p_{i+1},\dots,p_M$，所以当前集合恰好是 $\{p_1,\dots,p_i\}$。由定义 $c_i=\sum_{j=1}^{i}[p_j\le p_i]$，即 $p_i$ 在自己及之前这些数中的排名是 $c_i$。因此在当前集合中第 $c_i$ 小的数就是 $p_i$。$\square$

于是把“集合”看成一个长度 $M$ 的 01 序列（0 表示还在集合里）：
初始全 0；第 $i$ 步把第 $c_i$ 个 0 改成 1。答案 $p_k$ 就是第 $k$ 步被改的那个 0 的位置。

### 1.2 插入模型

还有一个等价视角，它更适合回答“第 $k$ 个元素的最终位置”。

**事实 2（插入模型）.** 从空序列开始，对 $i=1,2,\dots,M$ 依次把“元素 $i$”插入到当前序列的第 $c_i$ 个位置（即插到第 $c_i$ 个元素之前，$c_i$ 等于当前长度 $+1$ 时就是追加）。全部插完后，元素 $k$ 所在的位置就是 $p_k$。

**证明.** 对 $M$ 归纳。记插入完 $1..M$ 后的序列为 $L_M$，其中“元素 $i$”的值就是 $i$，$L_M$ 是一个排列。记 $\pi^{-1}(k)$ 为元素 $k$ 在 $L_M$ 中的位置。要证 $\pi^{-1}(k)=p_k$。

$k=M$ 时：元素 $M$ 最后插入，位置是 $c_M$，之后没有插入，所以 $\pi^{-1}(M)=c_M$。而 $\{p_1,\dots,p_M\}=\{1,\dots,M\}$，第 $c_M$ 小的数就是 $c_M$，故 $p_M=c_M$。

$k<M$ 时：把元素 $M$ 从 $L_M$ 中删掉，剩下的序列恰好是 $1..M-1$ 的插入结果（因为第 $M$ 次插入只是把元素 $M$ 放到第 $c_M$ 个位置，删掉它就还原）。设删掉后元素 $k$ 在位置 $q$，则

$$\pi^{-1}(k)=q+[\,q\ge c_M\,].$$

另一方面，把取 0 过程的第一步（取第 $c_M$ 个 0，即值 $c_M$）删掉后，剩下的数集是 $\{1,\dots,M\}\setminus\{c_M\}$。把大于 $c_M$ 的数都减 1，就得到一个 $1..M-1$ 上的同样形式的问题，其答案记为 $p'_k$。显然

$$p_k=p'_k+[\,p'_k\ge c_M\,].$$

由归纳假设 $p'_k=q$，两个式子右边相同，故 $p_k=\pi^{-1}(k)$。$\square$

插入模型的好处：$c_i=\min(b_{\text{块}(i)},i)$ 只影响“插到第几位”，而“元素 $k$ 最终在哪”可以逐个后续插入地追踪。

### 1.3 查询的归约（你的做法的理论基础）

固定查询 $(l,r,k)$。把查询展开序列的长度记作 $M=s_r-s_{l-1}$。令

$$s_i=\sum_{j=1}^{i}a_j,\qquad U=s_t-s_{l-1},$$

其中 $t$ 是满足 $s_t-s_{l-1}\ge k$ 的最小下标。也就是说，第 $k$ 个元素落在块 $t$ 里，并且到块 $t$ 结尾为止（含）一共有 $U$ 个元素。

**引理 1（初值）.** 设元素 $k$ 在块 $t$ 插入完成后的位置为 $x$。则

$$x=\begin{cases}k,&b_t>k,\\[2pt] b_t+U-k,&b_t\le k.\end{cases}$$

**证明.** 块 $t$ 覆盖查询内的位置 $s_{t-1}-s_{l-1}+1,\dots,U$。块内第 $j$ 个元素（$j$ 是查询内位置）的插入位置是 $\min(b_t,j)$。

- 若 $b_t>k$：元素 $k$ 插入后位置为 $k$。之后块内每个元素 $j>k$ 的插入位置是 $\min(b_t,j)\ge k+1>k$，即都插在元素 $k$ 当前位置的后面，不会把它往后挤。所以 $x=k$。
- 若 $b_t\le k$：元素 $k$ 插入后位置为 $b_t$。之后块内每个元素 $j>k\ge b_t$ 的插入位置都是 $\min(b_t,j)=b_t$。每次插在位置 $b_t$（不超过元素 $k$ 的当前位置），把它挤后一位。这样的插入一共有 $U-k$ 次，所以 $x=b_t+(U-k)$。$\square$

**引理 2（后续块的位移）.** 设元素 $k$ 在块 $i-1$ 结束后的位置是 $x$。那么块 $i$（$i>t$）的全部 $a_i$ 次插入，要么都插在元素 $k$ 当前位置之前（位置增加 $a_i$），要么都插在它之后（位置不变）。都插在之前的充要条件是 $x\ge b_i$。

**证明.** 块 $i$ 覆盖查询内位置 $P+1,\dots,P+a_i$，其中 $P=s_{i-1}-s_{l-1}$ 是块 $i$ 之前的元素个数。注意元素 $k$ 的位置 $x\le P$。

块内第 $r$ 个元素（$r=1,\dots,a_i$）的插入位置是 $q_r=\min(b_i,P+r)$，它们单调不减，且 $q_r\le q_{r-1}+1$。

- 若 $q_1\le x$：归纳可证第 $r$ 次插入时元素 $k$ 的位置是 $x+r-1$，而 $q_r\le q_1+(r-1)\le x+r-1$，所以第 $r$ 次也插在它之前。$a_i$ 次之后位置为 $x+a_i$。
- 若 $q_1>x$：则 $q_r\ge q_1>x$，每次插入都在元素 $k$ 之后，位置不变。

最后把条件化简。若 $b_i\le x$，则 $q_1=\min(b_i,P+1)\le x$（因为 $x\le P$ 且 $b_i\le x$）。若 $b_i>x$，则 $b_i\ge x+1$ 且 $P+1\ge x+1$，故 $q_1\ge x+1>x$。两种情况合起来正好是“$q_1\le x\iff b_i\le x$”。$\square$

由引理 1、2，答案就是

$$\mathrm{ans}=F(x),\qquad F=f_r\circ f_{r-1}\circ\cdots\circ f_{t+1},$$

其中 $f_i(y)=y+a_i$（若 $y\ge b_i$），否则 $f_i(y)=y$。这就是你的线段树要维护的东西。

## 2. 你的代码：问题定位与修正

### 2.1 逻辑错误：初值公式

你写的是

```cpp
LL K = min(LL(b[lt]), k) + suma[lt] - suma[l-1] - k;
```

即 $K=\min(b_t,k)+U-k$。当 $b_t\le k$ 时它等于 $b_t+U-k$（对）；当 $b_t>k$ 时它等于 $U$（错，应该是 $k$）。

**反例.** $n=1,a_1=5,b_1=100$，查询 $(l,r,k)=(1,1,2)$。

展开序列是 $5$ 个 $100$，$c_i=\min(100,i)=i$，即 $c=[1,2,3,4,5]$。
从后往前取第 $c_i$ 个 0：第 5 步取 $5$，第 4 步取 $4$，第 3 步取 $3$，第 2 步取 $2$。
所以 $p_2=2$。

你的代码：$U=5$，$K=\min(100,2)+5-2=5$；又因为 $t=r$，直接输出 $5$。错。
修正后：$b_1=100>k=2$，取 $K=k=2$，输出 $2$。对。

**对拍数据.** 用暴力（Fenwick 求第 $k$ 个 0）在小数据上随机构造 $7000$ 组、约 $42000$ 个查询：
- 你的公式错 $16396$ 个（约 $39\%$）；
- 修正公式错 $0$ 个。

**为什么性质 A 没暴露.** 性质 A 是 $a_i=1$。此时块 $t$ 只含位置 $k$ 一个元素，所以 $U=k$，于是

$$\min(b_t,k)+U-k=\min(b_t,k)=\begin{cases}k,&b_t>k,\\ b_t,&b_t\le k,\end{cases}$$

与正确公式完全相同。所以 $a_i=1$ 的数据全部通过，属于“错误被特例掩盖”。

### 2.2 建树部分是**对的**（逐段解释 + 为什么对）

你担心建树有错，实际没有。用上面的对拍，修正初值后 $7000$ 组随机数据全对。下面说明它为什么对。

每个结点存的是它管辖区间上所有 $f_i$ 的复合函数 $F$。可以证明 $F$ 一定是这种形状：

$$F(y)=y+\mathit{sum}[j]\quad\text{当 }\ \mathit{th}[j]\le y<\mathit{th}[j+1],$$

其中 $\mathit{th}[0]<\mathit{th}[1]<\cdots$ 是分界点（严格递增或允许重复），$\mathit{sum}$ 是前缀增量。理由：每个 $f_i$ 都是“在某个阈值之后整体加 $a_i$”，而 $F$ 的斜率恒为 1，所以 $F(y)-y$ 是单调不减的阶梯函数。

合并左右儿子时，$F=F_{\text{右}}\circ F_{\text{左}}$。左儿子的分界点原样保留；右儿子的每个分界点 $\theta$ 要换成 $\theta$ 在 $F_{\text{左}}$ 下的原像。由于 $F_{\text{左}}$ 严格递增，原像唯一。

设 $F_{\text{左}}$ 在区间 $[\mathit{th}[i],\mathit{th}[i+1])$ 上等于 $y+\mathit{sum}[i]$，它的值域是 $[\mathit{th}[i]+\mathit{sum}[i],\ \mathit{th}[i+1]+\mathit{sum}[i])$。所以 $\theta$ 的原像落在第 $i$ 段，当且仅当

$$\mathit{th}[i]+\mathit{sum}[i]\le \theta<\mathit{th}[i+1]+\mathit{sum}[i].$$

你的双指针正是这么找 $i$ 的：

```cpp
while (i < L-1 && t[x].th[i+1].first + t[x].sum[i] <= t[x].th[j].first) ++i;
```

找到之后，若 $\mathit{th}[i]+\mathit{sum}[i]=\theta$，原像就是 $\mathit{th}[i]$；否则是 $\theta-\mathit{sum}[i]$。你的两行代码分别对应这两种情况，正确。

还有一个细节你处理对了：当 $\theta$ 比 $F_{\text{左}}$ 的第一个分界点还小时，$F_{\text{左}}$ 在 $\theta$ 附近是恒等映射，原像就是 $\theta$ 本身。代码用

```cpp
if (t[x].th[0].first > t[x].th[j].first) continue;
```

跳过，保持原值，正确。

最后归并两个有序表并重算前缀和。归并时“相等先取左边”，这样相同分界点在数组中相邻且**后一个**的前缀和更完整；查询二分找的是“最后一个 $\mathit{th}\le K$”，因此取到的是完整前缀和，正确。

所以：**建树没有逻辑错误**。你在其它数据上的 WA 来自 2.1 的初值，RE 来自内存，TLE 来自常数。

### 2.3 RE 的原因：内存

$n=5\times10^5$ 时：

- 每个结点开两个长度 `r-l+1` 的 `vector`：分界点 `pair<LL,LL>`（16 字节）与前缀和 `LL`（8 字节）。
- 一层的长度和是 $n$，共约 $\lceil\log_2 n\rceil+1=20$ 层，所以总元素约 $10^7$。
- 仅数据：$10^7\times(16+8)=240$ MB。
- 还有 $2\times10^6$ 个结点、每结点两个 `vector` 头（各 24 字节）：$96$ MB。
- 合计约 $340$ MB。实测峰值 $372$ MB。

如果内存限制是 256 MB，这个写法一定 MLE（表现为 RE）。修法：改用一维数组、`int` 存分界点、合并去重。见第 3 节。

### 2.4 编译问题：`NDEBUG` 与 `assert`

你在第一行写了 `#define NDEBUG 1`，又用了 `assert`。C 标准规定定义了 `NDEBUG` 后 `assert` 仍应展开为空语句。但实际工具链（如本机 MinGW g++ 16）里 `assert` 会直接未声明，编译失败。

建议：调试用的 `assert` 删掉，或者用 `#ifndef NDEBUG` 包起来，不要靠 `#define NDEBUG` 关闭。

### 2.5 TLE 的原因

$n=q=5\times10^5$ 时实测：

| 版本 | yulan13 | yulan15 | yulan16 | yulan17 |
|---|---|---|---|---|
| 最小修正版 | 7.79 s | 8.64 s | 7.83 s | — |
| 常数优化版 | 2.61 s | 2.27 s | 2.64 s | 1.96 s |

时间几乎全在查询：每个查询分解出约 $16$ 个整结点，其中约 $10$ 个要二分（每次约 $9$ 步）。总计约 $5\times10^6$ 次二分、$4.5\times10^7$ 次比较，而且每次比较都是一次随机访存。

## 3. 常数优化：让 2log 挤进时限

目标：结构不变（还是“线段树 + 每个结点二分”），只改常数。下面 9 条按收益从大到小排列，全部在 `yulan_fast.cpp` 里实现。

**优化 1：一维数组代替 `vector<vector<>>`。**
预先算好每个结点在全局数组里的起始下标 `off[v]` 与长度。分界点放 `int* th`，前缀和放 `long long* ss`。
省掉 $96$ MB 的 `vector` 头，也省掉每个结点两次堆分配。建树从 $O(n\log n)$ 次分配变成 $0$ 次。

**优化 2：分界点用 `int`。**
需要证明分界点不会超过 $10^9$，也不会是负数。

**引理 3.** 建树过程中所有分界点都落在 $[1,10^9]$。

**证明.** 叶子结点存 $b_i\in[1,10^9]$。合并时只有两种可能：
- 右儿子的分界点 $\theta$ 比左儿子第一个分界点小：原样保留，仍在 $[1,10^9]$；
- 否则原像是 $\max(\mathit{th}[i],\theta-\mathit{sum}[i])$。由找到 $i$ 的条件 $\mathit{th}[i]+\mathit{sum}[i]\le\theta$ 得 $\theta-\mathit{sum}[i]\ge\mathit{th}[i]\ge 1$；又 $\theta-\mathit{sum}[i]<\theta\le10^9$。所以原像仍在 $[1,10^9]$。$\square$

而“加了多少”最多 $5\times10^{14}$，必须用 `long long`。所以：分界点 `int`，前缀和 `long long`。内存从 $240$ MB 降到 $120$ MB。

**优化 3：合并时去重。**
两个有序表归并时，若分界点相等就合并成一项，增量相加。于是每个结点的 `th` 严格递增，二分长度不超过“不同分界点个数”，实际数据上往往远小于区间长度。

**优化 4：每个结点存元数据 (最小值, 最大值, 总增量)。**
二分前先判：
- $x<\min$：函数在 $x$ 处是恒等，直接返回 $x$；
- $x\ge\max$：函数在 $x$ 处是 $x+$总增量，直接返回。
实测约 $40\%$ 的结点调用被这两条挡掉，完全不进二分。

元数据与 `off`、`cnt` 放进同一个 32 字节结构体，一次访存就能全部取回。

**优化 5：满二叉树 + 迭代式区间分解。**
取 $N=2^k\ge n$，用 `[l+N, r+N)` 的经典循环分解出 $O(\log n)$ 个整结点。不用递归，也不用传参。

**优化 6：批量读取元数据。**
区间分解先把结点编号收集到一个小数组，然后一次性把它们的元数据读进局部数组，最后再逐个作用。
这些读之间没有依赖，CPU 可以把多条 cache miss 并行发出去，而不是串行等待。

**优化 7：每个结点的分界点按 Eytzinger 布局存放。**
即把有序表按“完全二叉树的层序”重排。于是二分变成从根往下的走一条路径，访存集中在连续的几层上，比普通二分更容易命中缓存。
实现上先按普通有序布局把整棵树建完（因为父结点合并需要子结点的有序形式），再统一原地转换成 Eytzinger 布局。

**优化 8：两级定位 k 所在段。**
先按 1024 一块存块最大值，在约 $489$ 个块的数组里二分（全部在缓存里），再在块内二分。
把原来的 $19$ 次随机访存降到 $1\sim2$ 次。

**优化 9：快读快写 + 少用 `long long` 比较。**
`fread`/`fwrite` 手写缓冲；二分里只比较 `int`，最后一步才做 `long long` 加法。

**实测（本机，$n=q=5\times10^5$）：**

| 数据      | 最小修正版  | 优化版    | 峰值内存            |
| ------- | ------ | ------ | --------------- |
| yulan13 | 7.79 s | 2.61 s | 372 MB → 169 MB |
| yulan14 | 5.60 s | 0.80 s | 同上              |
| yulan15 | 8.64 s | 2.27 s | 同上              |
| yulan16 | 7.83 s | 2.64 s | 同上              |
| yulan17 | —      | 1.96 s | 同上              |

**建议.** 2log 做法本身就贴着时限（出题人的单 log 在本机也要 $2.2$ 秒）。如果评测机偏慢，最稳的是直接写单 log。下面给出单 log 做法。

## 4. $O((n+q)\log n)$ 做法

### 4.1 总览

思路分五步：

1. 把“有限序列上取第 $c_i$ 个 0”换成“无限序列上取第 $b_i,b_i+1,\dots$ 个 0”，并证明两者在块边界上一致（引理 4）。
2. 由此把查询化成“无限序列中的第 $x$ 个 0 的位置”，$x$ 与引理 1 相同（引理 5）。
3. 预处理每个前缀 $r$ 的无限序列：把块 $i$ 看成“在序列第 $b_i$ 个位置前插入 $a_i$ 个元素”，用平衡树按段维护（引理 6）。
4. 因为答案一定在 $[1,s_n]$ 内，把无限序列截断成长度 $s_n$，截断时用 $d_i=\min(a_i,\dots)$ 修正插入个数（引理 7）。
5. 每个位置标记“被哪个块占据”，按占据者的编号建可持久化线段树。查询时在两棵树上同时二分：一棵数“0”（编号 $\le t$），一棵数“1”（编号 $\in(t,r]$），答案就是第 $x$ 个 0 的位置（引理 8）。

### 4.2 引理 4：有限模型与无限模型

**无限模型的定义.** 有无穷多个 0（位置 $1,2,3,\dots$）。对 $i=M,M-1,\dots,1$：取当前第 $c_i$ 个 0，标记成 1。恒有 $c_i\le i$。

**引理 4.** 两个模型执行同样的 $M-i+1$ 步后，有限模型剩下的 $i-1$ 个 0，恰好是无限模型中**最靠左的 $i-1$ 个 0**。

**证明.** 对已执行步数归纳。开始（一步没做）时，有限模型有 $M$ 个 0，无限模型最靠左的 $M$ 个 0 就是位置 $1..M$，相同。

设处理到第 $i$ 步之前，有限模型的 $i$ 个 0 等于无限模型最靠左的 $i$ 个 0。第 $i$ 步两边都取第 $c_i$ 个 0。因为 $c_i\le i$，有限模型的第 $c_i$ 个 0 与无限模型的第 $c_i$ 个 0 是同一个（它一定在最靠左的 $i$ 个里）。两边都把它删掉，剩下 $i-1$ 个，仍然满足“有限 = 无限最靠左 $i-1$ 个”。$\square$

**引理 5（一个块的效果）.** 设处理某个块之前，有限模型的 0 集合等于无限模型最靠左的 $U$ 个 0，记它们为 $z_1<\dots<z_U$。该块有 $a$ 步，第 $j$ 步的排名是 $r_j=\min(b,j)$，其中 $j=U,U-1,\dots,U-a+1$。做完后，有限模型剩下的 $U-a$ 个 0 等于把无限模型中的 $z_b,z_{b+1},\dots,z_{b+a-1}$ 删掉后、剩下部分最靠左的 $U-a$ 个。

**证明.** 分三种情况。

- 若 $b\le U-a+1$：所有 $j\ge U-a+1\ge b$，故 $r_j=b$ 恒成立。每步删的是当前第 $b$ 个 0，于是依次删掉 $z_b,z_{b+1},\dots,z_{b+a-1}$。剩下 $z_1,\dots,z_U$ 中其余的 $U-a$ 个，正好是最靠左的 $U-a$ 个。与“删掉 $z_b..z_{b+a-1}$”一致。
- 若 $U-a+1<b\le U$：在 $j\ge b$ 的那些步（共 $U-b+1$ 步）删掉 $z_b,\dots,z_U$；在 $j=b-1,\dots,U-a+1$ 的这些步，$r_j=j$，即每步删当前最后一个。由于 $z_b..z_U$ 已被删，当前第 $j$ 个就是 $z_j$（$j<b$），所以依次删掉 $z_{b-1},\dots,z_{U-a+1}$。合起来删掉的正好是 $z_{U-a+1},\dots,z_U$（最后 $a$ 个），剩下 $z_1,\dots,z_{U-a}$。而 $b>U-a+1$，所以 $z_b,\dots,z_{b+a-1}$ 都在 $z_{U-a+1}$ 右边，删它们不影响前 $U-a$ 个。两边一致。
- 若 $b>U$：所有 $r_j=j$，每步删当前最后一个，删掉 $z_{U-a+1},\dots,z_U$，剩下 $z_1..z_{U-a}$。而 $z_b..z_{b+a-1}$ 更靠右，删它们也不影响前 $U-a$ 个。$\square$

引理 5 说明：**在块边界上，可以把“排名 $\min(b,j)$”当成“排名恒为 $b$”**。于是整个查询只看块级操作：块 $(a,b)$ 在无限序列里删掉第 $b,b+1,\dots,b+a-1$ 个 0。

### 4.3 引理 6：查询化成“无限序列第 $x$ 个 0”

**引理 6.** 对查询 $(l,r,k)$，令 $t,U$ 如 1.3 节，令

$$x=\begin{cases}k,&b_t>k,\\ b_t+U-k,&b_t\le k.\end{cases}$$

先按块 $r,r-1,\dots,t+1$ 的顺序在无限模型上操作，再取此时无限模型中第 $x$ 个 0，它的位置（下标）就是答案 $p_k$。

**证明.** 由引理 4，执行完块 $r..t+1$ 后，有限模型的 $U$ 个 0 等于无限模型最靠左的 $U$ 个 0。目标 0 一定在这 $U$ 个里，所以它的“位置”在两个模型里一样。

- $b_t\le k$：块 $t$ 的每步排名都是 $b_t$（因为 $j\ge k\ge b_t$）。第 $d$ 步删掉的是起始 $U$ 个 0 中的第 $b_t+d-1$ 个。目标是第 $d=U-k+1$ 步，所以是第 $b_t+U-k=x$ 个。
- $b_t>k$：块 $t$ 中位置 $j>k$ 的每一步，排名 $\min(b_t,j)\ge k+1$。所以这些步删掉的 0 在“当前第 $k$ 个”右边，不会影响前 $k$ 个。于是目标步（位置 $k$）删掉的是起始 $U$ 个 0 中的第 $k$ 个。$\square$

### 4.4 引理 7：构造全局标记序列

把“每个位置被哪个块占据（0 表示没被占据）”看成一串标记。需要构造这串标记，使得引理 6 里的“第 $x$ 个 0”可以直接查。

**构造.** 从空表开始，对 $i=1,2,\dots,n$ 依次执行：

> 在表的第 $b_i$ 个元素之前插入 $a_i$ 个标记为 $i$ 的元素（若表长小于 $b_i-1$，就插在末尾）。

初始时表可以看成无穷多个标记为 0 的元素。

**引理 7.** 上述构造得到的最终标记序列，与“按 $r,r-1,\dots,1$ 顺序做块级操作”得到的占据情况完全一致。

**证明.** 用不变式：对每个 $j\le i$，在构造进行到 $i$ 时，块 $j$ 的元素恰好是“未被块 $j+1..n$ 占据的元素”中的第 $b_j,b_j+1,\dots,b_j+a_j-1$ 个。

- 构造到 $j$ 时，表里是块 $1..j-1$ 的元素和无穷多个 0。此时“未被 $1..j-1$ 占据的元素”就是整张表。把 $a_j$ 个标记 $j$ 插到第 $b_j$ 个之前，就使它们是整张表的第 $b_j..b_j+a_j-1$ 个。
- 之后插入的块 $i>j$ 属于“被 $j+1..n$ 占据”的集合，按不变式它们不参与计数，所以块 $j$ 的排名在过滤集合里保持不变。

把“过滤掉 $j+1..n$ 后的排名 $b_j..$ ”翻译回块级操作，正是“块 $j$ 删掉当前未被更大块占据的元素中的第 $b_j..b_j+a_j-1$ 个”，与块级操作定义一致。$\square$

### 4.5 引理 8：截断到有限长度

引理 7 的表是无限长的，不能直接存。注意答案一定不超过 $M=s_r-s_{l-1}\le s_n$，所以只要保证前 $s_n$ 个位置正确即可。

**做法.** 先倒序算出每块实际插入的个数：

```
tl = s[n]
for i = n..1:
    d[i] = max(0, min(a[i], tl - b[i] + 1))
    tl -= d[i]
```

`tl` 最后的值记作 $T$。建表时先放 $T$ 个标记 0，再对 $i=1..n$ 把 $d_i$（而不是 $a_i$）个标记 $i$ 插到第 $b_i$ 个之前（超出表长就追加）。

**引理 8.** 这样建出的长度 $s_n$ 的表，等于引理 7 的无限表的前 $s_n$ 个位置。

**证明.** 记 $\ell_i$ 为“插完块 $1..i-1$ 后的表长”，则

$$\ell_1=T,\qquad \ell_{i+1}=\ell_i+d_i,\qquad \ell_{n+1}=T+\sum d_i=s_n .$$

又倒序循环里的 `tl` 在处理块 $i$ 时等于 $s_n-\sum_{j>i}d_j=\ell_i+d_i$，所以

$$d_i=\max\bigl(0,\min(a_i,\ \ell_i+d_i-b_i+1)\bigr).$$

当 $d_i>0$ 时它化简为 $d_i=\min(a_i,\ell_i+d_i-b_i+1)$，也就是

$$d_i=\min(a_i,\ \text{“窗口 }\ell_i+d_i-b_i+1\text{ 内能容纳的个数”}),$$

这正是一个不动点条件：把 $a_i$ 个元素插到第 $b_i$ 个之前后，截断到长度 $\ell_i+d_i$，恰好留下 $d_i$ 个。

用归纳：设插完块 $1..i-1$ 后有限表 = 无限表的前 $\ell_i$ 个。插入时无限表在第 $b_i$ 个之前插 $a_i$ 个，有限表插 $d_i$ 个。
- 若 $d_i=0$，说明 $b_i\ge\ell_i+1$，插入点在有限表末尾或更后面，前 $\ell_i$ 个不变。
- 若 $d_i>0$，由不动点条件，把无限表的插入截断到长度 $\ell_i+d_i$ 恰好留下 $d_i$ 个新元素，其余部分与旧表的前缀逐位相同。

所以插完后有限表 = 无限表的前 $\ell_{i+1}$ 个。归纳成立，最后得到前 $s_n$ 个。$\square$

### 4.6 引理 9：查询 = 静态序列上“第 $x$ 个 0 的位置”

在长度 $s_n$ 的表上，每个位置有一个标记（占据它的块编号，或 0）。对查询 $(l,r,k)$ 与引理 6 的 $x$：

**引理 9.** 答案 = 在前 $s_n$ 个位置中，只保留标记 $\le r$ 的位置、再数其中“标记 $\le t$ 的位置”，第 $x$ 个这样的位置的下标（在保留后的序列里从 1 开始数）。

**证明.** 引理 6 说答案是“块 $r..t+1$ 做完后，无限表第 $x$ 个 0 的位置”。

- 标记 $\le t$ 的位置就是“做完块 $r..t+1$ 后仍是 0”的位置。因为块 $i$ 占据的位置在构造里就是标记 $i$；块 $t+1..r$ 占据的标记在 $(t,r]$ 中，是 1；标记 $\le t$ 的块在块级操作里还没有执行（等价于把它们的占据撤销），所以仍是 0。
- 标记 $>r$ 的块在“前缀 $r$”里根本不存在。把它们删掉只改变下标，不改变相对顺序。所以在前缀 $r$ 的模型里，位置就是在“只保留 $\le r$ 的位置”后的下标。
- 引理 8 保证前 $s_n$ 个位置正确，而答案不超过 $s_n$，所以截断无害。

$\square$

### 4.7 主席树 + 双树同降

把表按“段”压缩：同一块插入的 $d_i$ 个元素是连续的，记成一段 $(长度, 编号)$。每次插入最多把一段切成两段、再加一段，所以总段数 $K=O(n)$（实际不超过 $2n+1$）。

按段的顺序（也就是表的下标顺序）给段编号 $1..K$，记段 $j$ 的长度为 $w_j$。

建可持久化线段树：`rt[k]` 表示“只考虑编号 $<k$ 的段”时，每个段位上的权重（$w_j$ 或 0）。于是：

- `rt[t+1]`：只含标记 $\le t$ 的段，即“0”；
- `rt[r+1]`：只含标记 $\le r$ 的段，即“存在的所有位置”。

查询要“第 $x$ 个 0 在只保留 $\le r$ 的位置后的下标”。在两棵树上同时从根往下走：

- 设左子树在 `rt[t+1]` 上的权重和为 $s_0$（左子树的 0 的个数），在 `rt[r+1]` 上的权重和为 $s_1$（左子树存在的总位置数）。
- 若 $x\le s_0$：第 $x$ 个 0 在左子树，两棵树都往左走。
- 否则：第 $x$ 个 0 在右子树，令 $x\leftarrow x-s_0$，并令答案累加 $s_1$（左子树里所有存在的位置都在它前面），两棵树都往右走。

走到叶子（某一段）时，剩下的 $x$ 是这一段内部第 $x$ 个位置。因为整段标记相同，段内下标就等于 $x$。于是

$$\text{答案}=\text{累加值}+x .$$

累加值恰好是“它前面有多少个存在的（标记 $\le r$）位置”，所以“累加值 $+x$”就是它在保留后序列里的下标，正是引理 9 要的东西。

### 4.8 复杂度

- 构造段：用平衡树（`solution.cpp` 用无旋 Treap）按段维护，$n$ 次切分 + 插入，每次 $O(\log n)$，共 $O(n\log n)$，段数 $O(n)$。
- 可持久化线段树：$K=O(n)$ 个段，每个段插入一次，$O(\log K)$，共 $O(n\log n)$ 个结点。
- 查询：先二分找块 $t$（$O(\log n)$），再一次双树同降（$O(\log n)$），总 $O(\log n)$。
- 总复杂度 $O((n+q)\log n)$，内存 $O(n\log n)$。

### 4.9 与 `solution.cpp` 的逐段对应

| `solution.cpp` 片段 | 含义 |
|---|---|
| `for (i=n;i;i--) d[i]=max(0,min(a[i], tl-b[i]+1)), tl-=d[i];` | 引理 8 的 $d_i$ 与 $T$ |
| `if (tl) _rt = create(tl, 0);` | 先放 $T$ 个标记 0 |
| `split(_rt, b[i]-1, l, r); _rt = merge(merge(l, create(d[i], i)), r);` | 在第 $b_i$ 个元素前插入 $d_i$ 个标记 $i$（无旋 Treap 按段维护） |
| `dfs(_rt)`：`w[++_tp]=len; nxt/head` | 按表的顺序给段编号，并按编号分桶 |
| `for (i=0..n) rt[i+1]=rt[i] + insert(段, w)` | 可持久化线段树，`rt[k]` = 编号 $<k$ 的段 |
| `i = lower_bound(s+1,s+n+1, k+s[l-1])-s;` | 找块 $t$ |
| `if (k>=b[i]) k = b[i]+s[i]-s[l-1]-k;` | 引理 6 的 $x$（`b[i]` 即 $b_t$，`s[i]-s[l-1]` 即 $U$） |

注意 `query` 里 `if (x<=s) ... else x-=s, res+=t[t[q].l].s` 的两步，正好是 4.7 节的“往左”和“往右并累加左子树存在的位置数”。

### 4.10 另一种构造（分治）

`题解2log.md` 提到也可以用分治合并出这 $O(n)$ 个段：递归处理左半和右半，右半的每个分界点在左半的“已占据长度”上加偏移。思路与线段树合并分段函数一样，只是把“合并”搬到离线。复杂度和 Treap 相同，常数更小，但写法更绕。这里只作为备选，不再展开。
